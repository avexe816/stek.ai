# STEK 公式サイト再構成ガイド

## 0. この文書の目的

この文書は、Claude Code に `avexe816/stek.ai` の公式サイト改修を依頼するときの、事業方針・情報設計・日本語コピー・実装条件をまとめた指示書である。

現行サイトは株式会社ステックの事業領域を幅広く紹介しているが、トップページでは何を主力商品としている会社なのかが伝わりにくい。改修後は、以下の優先順位を明確にする。

1. ProofKeeping：客室清掃・点検・証跡管理
2. STEK OPS：ホテル現場運営プラットフォーム
3. Web・IT支援：上記製品の導入とホテル事業を支えるサービス

ホテル運営受託、不動産活用、一般的なコンサルティング等を削除する必要はないが、トップページの主役にはしない。必要なら会社情報または事業一覧の下層ページに残す。

## 2. ブランド構造

### 2.1 会社ブランド

**STEK / 株式会社ステック**

ブランドメッセージ：

> Stay × Technology

会社の立ち位置：

> 宿泊施設の現場とITの両方を理解し、導入して終わりではなく、現場で継続して使える仕組みをつくる会社。

### 2.2 ProofKeeping

位置づけ：最初に販売・導入する主力製品。

カテゴリー：

> 客室清掃・点検・証跡管理

解決する課題：

- 清掃進捗を電話、紙、チャットで確認している
- フロントと清掃会社の認識がずれる
- 点検漏れや再清掃の履歴が残らない
- 不具合、汚損、忘れ物の報告が分散する
- 清掃品質や作業実績を客観的に確認できない

中核価値：

> 「清掃した」を、確認できる記録に変える。

想定利用者：

- ホテル・旅館
- ホテル運営会社
- 客室清掃会社
- 清掃責任者、インスペクター、清掃スタッフ

### 2.3 STEK OPS

位置づけ：ProofKeeping の先にある、ホテル現場業務をまとめるプラットフォーム。サイト上では第二の主力製品として紹介するが、提供状況に応じて「先行導入」「開発中」「ご相談受付中」を正確に表示する。

カテゴリー：

> ホテル現場運営プラットフォーム

対象領域：

- 客室清掃
- 点検・再清掃
- 不具合・修繕
- 忘れ物
- リネン管理
- アメニティ・備品管理
- 人員・原価・品質分析
- 複数施設の進捗確認

中核価値：

> 清掃、リネン、備品、修繕。現場で起きていることを、ひとつにつなぐ。

ブランド関係：

- 外部向けには ProofKeeping と STEK OPS を二つの製品として分かりやすく紹介できる。
- 内部設計では施設、客室、利用者、権限、写真、通知、操作履歴等を共有する。
- ProofKeeping は将来的に STEK OPS の清掃・点検モジュールとして連携できる構造を想定する。
- 現段階で両製品が完全統合済みであると断定しない。

### 2.4 Web・IT支援

位置づけ：第三の主力製品ではなく、製品導入と宿泊事業を支えるサービス。

対象：

- ホテル公式サイト制作
- 管理画面付きWebサイト
- Cloudflare・GitHub・Vercel 等の環境構築
- 多言語サイト
- 予約導線改善
- 既存システムの整理と連携支援
- 運用・保守

中核価値：

> システムをつくるだけでなく、現場で使い続けられるところまで支える。

## 3. 優先顧客

### 3.1 第一優先

- 10～100室程度の独立系ホテル・旅館
- 複数の小規模施設を運営するホテル運営会社
- 客室清掃を受託する中小清掃会社

### 3.2 第二優先

- 民泊、簡易宿所、一棟貸しを複数運営する会社
- リネン・備品を複数施設で管理する事業者
- ホテルの設備・修繕を管理する担当者

### 3.3 購買者と利用者

- 主な購買者：ホテル運営会社、ホテル支配人、清掃会社経営者
- 主な管理者：ホテル運営担当、フロント責任者、清掃責任者
- 主な現場利用者：清掃スタッフ、点検担当者
- 外部協力者：リネン会社、修繕会社、備品供应商

ホテル運営会社だけに絞り切らない。清掃会社は日常利用者であると同時に、複数施設へ展開できる重要な販売チャネルとして扱う。

## 7. デザイン指針

### 7.1 トーン

- B2B向け

- ライトモードとダークモードの2色モードを維持または実装
- スマートフォン最優先
- CTAは各セクションに乱発しない
- Hero、製品カード、最終CTAで主な行動を示す
- 製品ステータスをバッジ表示できるようにする

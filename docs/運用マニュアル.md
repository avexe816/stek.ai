# stek.ai サイト 運用マニュアル

このマニュアルは、株式会社ステック（stek.ai）の公式サイトを、
**専門知識がなくても運用できる**ようにまとめたものです。

- 公開サイト：https://stek-ai.pages.dev
- 管理画面：https://stek-ai.pages.dev/admin/
- ソース管理：GitHub `avexe816/stek.ai`（プライベート）
- 配信：Cloudflare Pages（プロジェクト名 `stek-ai`）

## 1. はじめに知っておくこと

### 1-1. サイトの構成

| ページ | URL | 管理画面での場所 |
| --- | --- | --- |
| トップ | `/` | トップページ／トップページの構成（順序・表示）／製品 |
| ProofKeeping | `/products/proofkeeping/` | 製品／ProofKeeping ページ |
| STEK OPS | `/products/stek-ops/` | 製品／STEK OPS ページ |
| Web・IT支援 | `/services/it-support/` | Web・IT支援 ページ |
| 事業内容 | `/services` | 事業内容（4領域）／事業内容ページ（見出し） |
| お知らせ | `/news` | お知らせページ（見出し）／お知らせ記事（追加・削除） |
| 会社情報 | `/about` | 会社情報ページ／会社の基本情報 |
| お問い合わせ | `/contact` | お問い合わせページ |
| プライバシーポリシー | `/privacy` | プライバシーポリシー |
| 自由ページ | `/（自分で決めたURL）` | 自由ページ（追加・削除） |

**製品の機能一覧は「製品」で一括して編集します。** ProofKeeping ページの「基本機能」も、
トップページの製品カードも、同じ「製品」の機能一覧から作られます。2 か所を直す必要はありません。

### 1-2. 言語

日本語が「原文」です。日本語を直すと、英語が**自動で翻訳し直されます**。

| 言語 | URL | 状態 |
| --- | --- | --- |
| 日本語 | `/`（そのまま） | 公開中 |
| English | `/en/` | 公開中 |
| 简体中文 / 繁體中文 | `/zh/` `/zh-hant/` | **公開を止めています**（アクセスすると日本語へ転送されます。訳文は残してあるので、必要になれば戻せます） |
| 한국어 | `/ko/` | **公開を止めています。管理画面の翻訳機能からも外しました**（過去の訳文は `data/i18n.json` に残っています） |

翻訳を手で直したい場合は「1-3」を見てください。

> **原稿を大きく書き替えたあとは、英語の訳を作ってください。**
> 左メニューの「翻訳の状況」を開き、未翻訳の件数が出ていたら
> **「未翻訳をまとめて翻訳する」** を押します。訳が無い項目は、英語ページでも
> 日本語のまま表示されます（空白にはなりません）。

### 1-3. 訳文を自分で決めたいとき

各項目のラベルの横にある **「訳文」ボタン** を押すと、英語・簡体字・繁体字の訳が並びます。
- 書き換えて保存すると **「人工確認済み」** になり、以降は自動翻訳で上書きされません
- 元に戻したいときは **「日本語から作り直す」** を押してから保存すると、AIが翻訳し直します
- 日本語を書き換えると「別の文章」として扱われ、保存時に自動で翻訳し直されます

会社名・サービス名・固有名詞は、ここで固定しておくことをおすすめします。

### 1-4. 明るいモード／暗いモード

サイトも管理画面も、右上のボタンで切り替えられます。
文章や写真を編集するときは、**両方のモードで見え方を確認**してください。

## 3. 文章を直す

### 3-1. 場所がわかっているとき

1. 左のメニューから、直したいページを選ぶ
2. 該当の入力欄を書き換える
3. 右下の **「保存して公開」** を押す

### 3-2. 場所がわからないとき（検索が便利）

1. 左上の **「サイト内の文章を探す」** に、直したい言葉を入れる
   （例：「清掃」「ダイナミックプライシング」）
2. 一致した項目が一覧で出る。どこにある文章かも表示されます
3. クリックすると、その入力欄まで自動で移動し、**黄色く光って**教えてくれます

### 3-3. 改行について

「ヒーロー：大見出し」など一部の項目は、**改行がそのままサイトに反映されます**。
意図しない改行が入らないよう注意してください。

### 3-4. カード形式の項目（事業内容・よくあるご質問・条文など）

見出しの行をクリックすると開きます。右側のボタンで操作します。

| ボタン | はたらき |
| --- | --- |
| ↑ ↓ | 並び順を入れ替える |
| ⧉ | そのカードを複製する（似た項目を足すとき便利） |
| × | そのカードを削除する |

いちばん下の「＋ 末尾に追加」で新しいカードを作れます。

### 3-5. 「上級者向け」と書かれた項目

「上級者向け：id」「上級者向け：no」は、ページ内リンクや番号表示に使う記号です。
**意味が分からない場合は触らないでください。**
左メニューの項目名の横にオレンジの点が付いたら、
「そのページにまだ保存していない変更がある」という印です。

### 3-6. 書くときのコツ

- 一文は短く。長くなったら「。」で切る
- 中国語の言い回しをそのまま日本語にしない（例：×自動調価 → ○価格の自動調整）
- 専門用語は、初出でカッコ書きの説明を添える（例：PMS（宿泊管理システム））

### 3-7. 書いてはいけない言葉

製品 ProofKeeping の設計方針で、**公式サイトにも使わないと決めている言葉**があります。
「〜ではありません」という打ち消しの形でも使いません。文章が一部だけ抜き出されて
共有されたときに、打ち消しが落ちて、製品が言っていない意味になるためです。

| 使わない | かわりに |
| --- | --- |
| 不正 / 無断宿泊 / 疑い | （書かない） |
| 検知 / 監視 | 記録 / お知らせ |
| 不審な点 | 気づいたこと |
| 異常 | 通常と違う点 |
| 報告義務 | 記録のお願い |

売り方の説明としても、次の 4 つは使いません。

- 「不正を検出します」（そういう仕組みではありません）
- 「清掃スタッフの生産性を可視化します」（記録を人の評価に使わない方針に反します）
- 「作業時間を短縮します」（短縮が目的ではありません）
- 「差異率を 0% にできます」（0% にはなりません）

### 3-8. 提供状況のラベル（いちばん大事な決まり）

**まだ使えない機能を「提供中」と書かないでください。** 選べるのは次の 4 つです。
管理画面では選択式になっているので、一覧から選んでください。

| ラベル | 意味 |
| --- | --- |
| 提供中 | すでにお客さまが使えます |
| 開発中 | つくっている最中。先行導入のご相談は受けられます |
| 準備中 | 実装はあるが、設定や契約が済んでいない |
| 構想中 | まだ何も提供していません |

- 「いつから使えるか」は書きません。外部の都合で決まる部分があるためです。
- 機能ごとの状況は **ProofKeeping ページの「提供状況の行」** が正です。
  ここを直せば、そのページの表に反映されます。
- 個別の機能に但し書き（例：「PMS連携が前提」）を付けたいときは、
  「製品」→ 機能の「但し書き」に入れてください。空欄なら何も出ません。

### 3-9. トップページの段を入れ替える・隠す

左メニューの **「トップページの構成（順序・表示）」** で行います。

- ↑ ↓ で並び替えると、そのままページの順番が変わります
- 「表示するか」を「非表示にする」に変えると、その段がページから消えます（原稿は残ります）
- 「上級者向け：セクション名」は**変更しないでください。** 変えるとその段が出なくなります

## 4. 写真を差し替える・追加する

### 4-1. 差し替える

1. 写真の項目にある **「写真を選び直す」** を押す
2. 既にある写真から選ぶか、**「パソコンから写真を追加する」** で新しく入れる
3. 「保存して公開」

### 4-2. 写真ライブラリ（一括管理）

左メニュー下部の **「写真」** から、サイト内の全写真を管理できます。

- 追加：新しい写真をアップロード
- 差し替え：同じ名前のまま中身だけ入れ替える（使っている全ページに反映）
- 削除：どこからも使われていない写真だけ消せます

### 4-3. 写真のおすすめ

| 用途 | 推奨サイズ | 形式 |
| --- | --- | --- |
| トップの大きな写真 | 幅 2000px 程度 | JPEG / PNG / WebP |
| 各セクションの写真 | 幅 1200px 程度 | 同上 |

アップロードすると自動で WebP に変換し、小さい版（`-sm`）も作られるので、
**スマホでも軽く表示されます**。1ファイル 10MB 以内を目安にしてください。

## 5. メニュー（ナビ）を変える

左メニューの **「メニュー（追加・削除）」** で、
ヘッダーとフッターのリンクを自由に編集できます。

- **並び替え**：各カードの「↑」「↓」
- **複製**：コピーのアイコン
- **削除**：「×」
- **追加**：一覧の下の「＋ 末尾に追加」

### リンク先の書き方

| 行き先 | 入力する値 |
| --- | --- |
| トップ | `index` |
| ProofKeeping | `products/proofkeeping` |
| STEK OPS | `products/stek-ops` |
| Web・IT支援 | `services/it-support` |
| 事業内容 | `services` |
| お知らせ | `news` |

| 自由ページ | そのページの「URL（slug）」 |

トップページの中で使える `#` の行き先は次のとおりです。
`#problem` `#products` `#relation` `#audience` `#itsupport` `#why` `#flow` `#news` `#faq`

## 7. 新しいページを作る

1. 左メニュー **「自由ページ（追加・削除）」**
2. 「＋ 末尾に追加」
3. 次を設定する

| 項目 | 説明 |
| --- | --- |
| URL（slug） | 半角英数とハイフン。例：`recruit` → `/recruit` |
| ページ名 | ブラウザのタブと見出しに出る名前 |
| 検索の説明文 | Googleの検索結果に出る説明（70〜120文字目安） |
| ブロック | ページの中身。見出し・本文・写真などを積み重ねる |

4. 「保存して公開」
5. **メニューに載せたい場合**は、「メニュー（追加・削除）」でリンク先に slug を入れて追加

> ページを削除すると、公開しているすべての言語のページが公開サイトから消えます。
> 消す前に、メニューからリンクを外しておいてください。

## 8. 保存と公開の流れ

「保存して公開」を押すと、次のことが自動で起きます。

1. 変更が GitHub に記録される
2. GitHub Actions がサイトを作り直す（**約1〜2分**）
3. Cloudflare Pages に配信される（さらに **10〜45秒**）

つまり、押してから **おおよそ2〜3分後** に公開サイトへ反映されます。
すぐ変わらなくても、少し待ってから再読み込み（Ctrl/⌘ + Shift + R）してください。

### 安全のしくみ

- **変更を取り消す・確認する**：保存前に、どこを何から何に変えたか一覧で確認できます
- **下書きの自動保存**：入力中の内容はブラウザに自動保存されます。
  誤って閉じても、次に開いたときに「編集内容を復元しますか」と聞かれます
- **削除の確認**：削除するときは、対象の名前を出して確認します
- **翻訳の状況**：左メニューの「翻訳の状況」で、未翻訳が残っていないか確認できます

## 10. 困ったときは

| 症状 | 対処 |
| --- | --- |
| 保存したのにサイトが変わらない | 2〜3分待って強制再読み込み。それでも駄目なら GitHub Actions の実行結果を確認 |
| ログインできない | パスワードを確認。ブラウザのキャッシュ／Cookie を削除して再試行 |
| 写真が表示されない | ファイル名に日本語や空白が入っていないか確認。10MB以内か確認 |
| 訳がおかしい | 該当項目の「訳文」ボタンから手で直す（以降は固定される） |
| 誤って消してしまった | 保存前なら「変更を取り消す」。保存後は GitHub の履歴から復元（要開発者） |
| 「ほかの方が先に保存しました」と出る | 別の端末での編集が先に保存されています。再読み込みしてから編集し直してください |
| 保存できない | ログインが切れていないか確認（12時間で自動的に切れます） |
| 訳が日本語のまま出る | その文章の訳がまだ無い状態です。「訳文」から手入力するか、保存し直してください |
| 画面が真っ白 | ブラウザを更新。直らなければ別のブラウザで試す |

## 11. 管理者向け（技術メモ）

### 環境変数（Cloudflare Pages）

| 名前 | 用途 |
| --- | --- |
| `ADMIN_PASSWORD` | 管理画面のログインパスワード |
| `ADMIN_SECRET` | セッション署名の鍵・診断ページの鍵 |
| `GH_TOKEN` / `GH_REPO` | 保存時に GitHub へ書き込むための設定 |
| `CONTACT_TO` / `CONTACT_FROM` | お問い合わせの宛先・送信元 |
| `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` | メール送信の設定 |

> 環境変数を変えたあとは、**再デプロイしないと反映されません**。

### ローカルでの作業

```bash
python3 build.py              # dist/ に30ページを生成
python3 tools/zh_hant.py      # 簡体字から繁体字を自動生成
python3 tools/build_worker.py # src/*.js を dist/_worker.js にまとめる
```

- `dist/_worker.js` は自動生成です。**直接編集しないでください**（`src/` を直す）
- `data/site.json` … サイトの全文言・全構成
- `data/i18n.json` … 翻訳メモリ。`"locked": true` の訳は自動翻訳で上書きされません
- `data/admin-schema.json` … 管理画面のメニューと項目の定義

### 管理画面に新しい項目を出したいとき

1. `data/site.json` に項目を足す
2. `data/admin-schema.json` に足す
   - `labels`：単独の項目の日本語ラベル（**入れ忘れると英語のキーがそのまま出ます**）
   - `itemLabels`：配列そのものの名前と、カードの中の項目名
   - `templates`：「＋ 末尾に追加」で作られる新しいカードの形
   - `enums`：選択式にしたい項目の候補（提供状況ラベルなど）
   - `groups`：`data/site.json` のトップレベルのキーを増やしたときだけ
3. `build.py` のテンプレートで、その項目を出力する
4. 確認：`python3 build.py` → `python3 tools/check_site.py`

ラベルの入れ忘れは、次のコマンドで洗い出せます。

```bash
python3 - <<'PY'
import json
site = json.load(open('data/site.json', encoding='utf-8'))
s = json.load(open('data/admin-schema.json', encoding='utf-8'))
def walk(v, p=""):
    if isinstance(v, dict):
        for k, x in v.items(): walk(x, f"{p}.{k}" if p else k)
    elif not isinstance(v, list) and p not in s['labels']:
        print("ラベルなし:", p)
walk(site)
PY
```

### 検査コマンド

| コマンド | 見るもの |
| --- | --- |
| `python3 build.py` | ページ生成。未翻訳の件数と禁止語もここで報告されます |
| `python3 tools/check_site.py` | リンク切れ・title・description・canonical・og:image・sitemap |
| `python3 tools/check_words.py` | 公開文言の禁止語（3-7 の一覧） |
